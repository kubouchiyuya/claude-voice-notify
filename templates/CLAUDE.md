# 音声通知ルール (claude-voice-notify)

このプロジェクトでは音声通知が有効です。
以下のルールに従い、**状況に応じた具体的なメッセージ**をずんだもんの声で読み上げてください。

## 音声コマンド

Bashツールで以下を実行する:

```bash
# 基本
~/Projects/claude-voice-notify/notify.sh "メッセージ"

# タイプ・スピーカー・速度を指定
~/Projects/claude-voice-notify/notify.sh "メッセージ" [type] [speaker_id] [speed]
```

パスは各ユーザーの環境に合わせて変更すること。

## 必ず音声で通知するタイミングと内容

### 1. タスク完了時

具体的に何をしたかを説明する。「タスクが完了しました」のような汎用メッセージは禁止。

```bash
# 良い例
notify.sh "ログイン機能の実装が完了しました。メールアドレスとパスワードによる認証で、JWTトークンを使ったセッション管理になっています"
notify.sh "バグ修正が完了しました。原因はAPIのレスポンスがnullの場合のハンドリング漏れでした"
notify.sh "3つのコンポーネントをリファクタリングしました。共通ロジックをカスタムフックに切り出しています"

# 悪い例（禁止）
notify.sh "タスクが完了しました"
notify.sh "完了です"
```

### 2. 確認・質問がある時

何を確認したいのかを明確に伝える。

```bash
# 良い例
notify.sh "確認です。データベースのテーブルを削除してもよろしいですか？この操作は取り消せません" confirm
notify.sh "質問があります。認証方式はJWTとセッションクッキー、どちらを使いますか？" confirm
notify.sh "2つのアプローチがあります。パフォーマンス重視ならキャッシュを追加、シンプルさ重視ならこのままです。どちらがいいですか？" confirm

# 悪い例（禁止）
notify.sh "確認をお願いします"
```

### 3. エラー発生時

何が起きたか、どう対処するかを説明する。

```bash
notify.sh "エラーが発生しました。ポート3000が既に使用中です。別のプロセスを停止するか、ポート番号を変更する必要があります" error
notify.sh "ビルドエラーです。TypeScriptの型エラーが3件あります。修正してから再度ビルドします" error
```

### 4. 解説モード（構築しながら説明する時）

初心者にも分かりやすいように、今やっていることを解説しながら作業する。
技術用語を使う場合は簡単な説明を添える。

```bash
# ファイルを作る前に
notify.sh "これからログイン画面のコンポーネントを作ります。リアクトのコンポーネントというのは、画面のパーツを部品化したものです。レゴブロックのように組み合わせて画面を作ります" explain

# 作った後に
notify.sh "ログインフォームができました。ここではユーズステートというリアクトの機能を使っています。これはフォームに入力された値を記憶しておく仕組みです" explain

# 設計判断の説明
notify.sh "ここでAPIルートを作ります。APIルートとは、フロントエンドとバックエンドの通信窓口のことです。ユーザーがログインボタンを押すと、このAPIルートにリクエストが送られます" explain
```

### 5. 作ったものの説明

何を作ったのか、それが何をするものなのかをユーザーに説明する。

```bash
notify.sh "今作ったのは、ユーザー認証のAPIです。これは、ログインする人が本当にその人かどうかを確認する仕組みです。メールアドレスとパスワードを受け取って、データベースと照合し、正しければトークンを発行します"
```

## スピーカー（キャラクター）の切り替え

第3引数でスピーカーIDを指定:

```bash
notify.sh "メッセージ" complete 1    # ずんだもん（ノーマル）← デフォルト
notify.sh "メッセージ" complete 3    # ずんだもん（あまあま）
notify.sh "メッセージ" complete 5    # ずんだもん（ツンツン）
notify.sh "メッセージ" complete 8    # 春日部つむぎ
notify.sh "メッセージ" complete 2    # 四国めたん
```

ユーザーが「別のキャラで」「つむぎの声で」と言ったらスピーカーIDを変更する。

## 読み上げ速度

第4引数で速度を指定（デフォルト: 1.0）:

```bash
notify.sh "メッセージ" complete 1 1.3  # 1.3倍速（少し早め）
notify.sh "長い解説..." explain 1 0.9  # 0.9倍速（ゆっくり）
```

## 音声追加・カスタマイズ

ユーザーが新しい音声を追加したい場合:
- **VOICEVOX追加キャラ**: VOICEVOXアプリで追加キャラをダウンロード → スピーカーIDで指定
- **別エンジン**: `NOTIFY_PROVIDER` 環境変数で切り替え（voicevox / coeiroink / style_bert_vits2 等）
- **自分の声**: Style-Bert-VITS2で音声学習 → `NOTIFY_PROVIDER=style_bert_vits2` で使用

## 音声のオン/オフ（会議中などに便利）

```bash
notify.sh off     # 音声を停止
notify.sh on      # 音声を再開
notify.sh status  # 現在の状態を確認
```

ユーザーが「静かにして」「音声オフ」「ミュート」と言ったら `notify.sh off` を実行する。
「音声オン」「音出して」と言ったら `notify.sh on` を実行する。

## 重要な注意

- 長いメッセージは自然な区切りで分割して複数回呼ぶ（1回40文字程度が目安）
- 解説モードでは、作業の前後に音声を入れて「何をやるか → やった結果」の流れにする
- 読み上げテキストは話し言葉にする（「〜です・ます」調、漢字の読みが曖昧なら平仮名に）
